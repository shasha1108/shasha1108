> 给说不清的东西，留一台会回应的仪器。

这里不是项目陈列柜，也不是一张技能清单。它是一间仍在工作的仪器室：图像、手势、时间与记忆被放进可被重访的小系统，等人靠近，才开始发生。

> 我不做万能 Agent。
> 我做能接住一种具体创作判断的仪器。
> 有的接住说不清的情绪，有的接住创作，有的接住证据。

## 02 / 三件旗舰

### [永生花工坊](https://shasha1108.github.io/healing-visual-lab/eternal-bloom/eternal-bloom.html)

> 调好一朵花的每个参数，封进玻璃钟罩，它就替你一直开着。

1. **它接住什么** — 接住“我怕它会消失”的悬空感：一朵花被允许一直开着，而不是被催着在一刻说清自己。
2. **用户必须做什么** — 用户必须先亲手调节花的颜色、形态或节律；不是被动领取一份已经替她完成的安慰。
3. **系统如何判断** — 系统只读取明确的参数与触碰，不猜测情绪，也不替人给这朵花命名。
4. **世界怎样回应** — 参数与触碰改变花的状态，声音随之出现；回应可见，却不催促解释。
5. **为什么只能这样交互** — 只有先做出一个微小选择，钟罩里的“持续开着”才是来访者亲手留下的照料，而不是自动化的背景动画。

<a href="https://shasha1108.github.io/healing-visual-lab/eternal-bloom/eternal-bloom.html" target="_blank" rel="noopener">打开 ↗</a>

### [瓶装宇宙](https://shasha1108.github.io/healing-visual-lab/bottled-cosmos/bottled-cosmos.html)

> 把整个宇宙装进一只玻璃瓶——每颗恒星的一生，只有三十秒。

1. **它接住什么** — 接住“来不及看完这么多”的巨大与短暂：每颗恒星的一生只有三十秒，仍可以被安放进一只瓶。
2. **用户必须做什么** — 用户必须决定何时靠近并打开瓶口；主页不在背后替任何人运行宇宙。
3. **系统如何判断** — 系统只把“进入”这一次明确选择当作开始条件，并以有限时长组织恒星的显影、变化与熄灭。
4. **世界怎样回应** — 点击进入后，瓶内星体在自己的三十秒里运行；玻璃边界让巨大的尺度仍像能被捧住。
5. **为什么只能这样交互** — 宇宙必须由人亲自打开，短暂才不是被算法抢走的注意力，而是一段被选择的停留。

<a href="https://shasha1108.github.io/healing-visual-lab/bottled-cosmos/bottled-cosmos.html" target="_blank" rel="noopener">打开 ↗</a>

### [青绿·层峦](https://shasha1108.github.io/healing-visual-lab/layered-mountains/layered-mountains.html)

> 触之即散，聚散随缘

1. **它接住什么** — 接住那些既不想被固定、也不想被视作消失的时刻：散开并不等于失去，聚拢也不等于必须留下。
2. **用户必须做什么** — 用户必须把视线或指针停在山势上；不需要提交一段自我说明，只需要愿意停留。
3. **系统如何判断** — 系统通过光标射线与粒子景观的相对位置判断局部扰动，不从来访者身上推断任何心理状态。
4. **世界怎样回应** — 青绿层峦在局部关系中松动、显现、重新聚合；回应不是弹窗，而是一处山势被重新看见。
5. **为什么只能这样交互** — 只有让靠近改变观看关系，作品才保留“聚散随缘”的余地；把它做成点击领奖会取消这种余地。

## 04 / 三张系统工作台

### 01 · 感受仪器

**PRIVATE SYSTEM / NO SOURCE LINK**

**成员** — healing-space / pixel-bloom / Healing Visual Lab

把难以命名的感受做成必须由人完成、并会给出回应状态的体验。

**脱敏流程** — `感受 → 隐喻 → 不可替代动作 → 回应状态`

### 02 · 创作仪器

**PRIVATE SYSTEM / NO SOURCE LINK**

**成员** — content-creation-router / inner-voice / echo-caption / duotone-screenprint / social-video-editor / h5-publish

把创作输入交给场景判断与专业执行器，并把最终确认保留给用户。

**脱敏流程** — `输入 → 场景判断 → handoff → 专业执行器 → 用户确认`

### 03 · 证据仪器

**PRIVATE SYSTEM / NO SOURCE LINK**

**成员** — content-growth-advisor / yunye-growth-lab / creator-growth-workbench

把增长与创作判断拆回事实、推断和待验证项，再以可复盘的实验继续。

**脱敏流程** — `事实 → 推断 → 待验证 → 单变量实验 → 真实复盘`

## 05 / 我拒绝自动化什么

- 不把缺失数据当成 `0`。
- 不把发布完成写成增长成立。
- 不替用户确认创作意图。
- 不让公式替代真实读者目标。
- 不让点击成为没有隐喻意义的特效。
- 不用万能 Agent 掩盖专业判断的缺失。
